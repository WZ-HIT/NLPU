# sdd-results 轮次版面

适用版本：Dashboard 1.7.2。展示层使用独立模块 `batch/results_ui.py`；实验配置、ledger、seal 和评分算法保持原职责。

## 使用

结束原来的 `sdd-results` 服务（在服务终端按 Ctrl+C），然后重新运行：

```bash
sdd-results
```

打开终端给出的地址。首页现在选择**完整实验轮次**，不再混排批次卡片和 PR 卡片。当前已明确登记：

- `测试方法定位 · testcase-002`：30 + 30 + 38 PR，合计 98 PR / 294 个 Detect 方法目标。
- `历史对照 · 文件级首轮（98 PR）`：历史三组的集合；它们原来的轮次标签不同，显示集合不声称运行条件相同或全部完成。

首页只负责选择，比较由“比较轮次”进入；未归组的历史批次在“历史实验”内查看。

## 页面层次

1. **轮次首页**：每轮一行，按记录更新时间倒序，显示名称、已核对 PR 数、状态和简短条件。模型与预算缺少已核验的历史记录时显示未记录 / 未核验，不从当前配置推测。
2. **轮次详情**：概览 / PR 列表。
   - 概览按进度、定位指标、token 用量、执行组备注、折叠技术信息排列。
   - 默认 testcase + PR 宏平均；可切换同范围文件级和总体微平均；历史文件级放在兼容折叠区。
   - 缺失、过期、无效评分单独标明。失败零分沿用 v3 已记录口径；无正目标与不可评分不伪装成零分。覆盖分母保留所有已核对的 Detect 目标。
   - token 含失败与全部重试。缺少返回用量时只显示已知小计和记录覆盖，不估算费用。
   - PR 列表每 PR 一行，只展示标题、三个方法状态和详情入口；支持搜索、执行组、失败及未完成筛选。
3. **PR 详情**：紧凑方法比较表 + 三个方法标签页。最新预测 / 失败原因与本次用量优先显示；规划、原始 JSON、日志及历史尝试折叠。历史尝试日志从已核对 ledger 的引用进入，不扫描孤立日志充当正式尝试。
4. **比较轮次**：选 2–3 轮，以共同 PR 为默认范围，保留范围内的失败与未完成目标；评分和 token 使用同一 PR 集合。协议、base 索引或标签身份无法对齐时明确标识；模型 / 预算未知时只作描述性对照、不自动排名。各轮完整范围结果可展开。

旧 `/experiment/<token>` URL、`sdd-results list`、`sdd-results report` 和旧历史来源继续可用。独立导出的 HTML 可浏览；备注编辑在在线轮次页面提供。

## 两阶段生产定位实验（1.7.0）

首页新增“当前实验 · 生产定位→测试更新 · 首批30 PR”。该轮是独立的90组、最多180阶段实验，不覆盖原testcase-002及历史文件级记录。

- 概览显示组完成率、生产／测试阶段状态、已返回完整usage的rollout已知小计和覆盖数；模型与预算取本轮冻结配置。
- PR列表保留原30名单及标题，逐方法进入生产候选与测试更新判断详情，false／null及缺失更新理由都保留。
- 每15秒读取新快照；状态变化时刷新，输入备注等编辑操作期间不刷新。超过90秒未更新的运行中快照标为状态未确认，不冒称进程仍存活。
- 全批预测封存并完成宿主评分前，生产三级及测试双粒度指标显示未评分。评分后显示正任务macro／micro、全PR micro、完成率和无正标签失败数；失败空预测不冒充正确负判断。
- 历史比较仅展示启动时冻结且base／index／labels对齐的首批30报告，其他跨协议组合不自动计算差值，不混入旧轮其余68个PR。

该展示provider为`production-test-v1`，通过目录条目的`snapshot`及`manifest_sha256`绑定只读、无gold的发布快照。快照由独立实验控制器定期写到`Log/viewer/production-first30-v1.json`；浏览端不导入实验runner、不读取宿主gold或阶段原始日志、不触发模型调用或评分。JSON自哈希、manifest身份、完整PR×方法集合和禁用字段均验证，GET不写文件。新API为`/api/production-results/<round-id>`，PR详情为`/production-pr/<round-id>/<pr>`。

实验运行位于独立worktree，界面代码位于主工作区；二者不共享写入runner。需要重启已有sdd-results服务使1.7.0代码生效。

## 显式归组和名称

### D 组 TI 实验实时进度（1.7.2）

沿用同一服务及首页，新增 `test-intention-run-v1` 展示来源。D 组入口为
`/round/scrapy-ti-d-first30-20261114-v1`；只读进度 API 为
`/api/intention-results/scrapy-ti-d-first30-20261114-v1`。

- 展示目录的 `run_root` 和 `plan_sha256` 绑定本轮独立执行目录与冻结计划。
- 准备检查按 PR 计数，正式实验按 PR×SDD 目标计数；准备完成不计作正式执行或定位正确。
- 显示逐 PR、逐方法状态、正式启动数、已封存、失败/阻塞、运行记录及待运行数。
- 浏览器每 15 秒只读轮询，局部更新文本与进度条，保留搜索输入。读取失败保留上次状态并明确提示；控制进程按 PID 和启动标识核对，退出后不继续声称运行。
- 只读取冻结计划、准备摘要、SQLite 只读 journal 和控制器阶段/完成记录。API 按允许字段构建响应，不传出原始 journal detail、宿主路径、凭据或 gold。GET 不启动准备、模型调用、重试或评分。
- C 为历史参考，本次仅运行 D；比较页不自动计算跨协议或非同期受控差值。最终定位质量以宿主机完成后的结果报告为准。

修改后需重启展示服务；不要重启实验控制器。服务需带 benchmark 导入路径，例如：

```bash
PYTHONPATH=/home/wangzuohit/NLPU/sdd-bench/scrapy-sdd \
  python3 sdd-bench/scrapy-sdd/tools/sdd-results.py serve --host 127.0.0.1 --port 8765
```

离线验收包含只读 HTTP、分母与状态、进程退出、计划变更拒绝和浏览器轮询逻辑：

```bash
PYTHONPATH=sdd-bench/scrapy-sdd python3 -m unittest tests.test_sdd_intention_results
```

`batch/viewer/rounds.json` 是展示目录：

```json
{
  "version": 1,
  "rounds": [{
    "id": "scrapy-testcase-003",
    "name": "Scrapy · testcase-003",
    "groups": [
      {"batch_id": "round-实际首组ID", "name": "首批 30 PR"},
      {"batch_id": "round-实际次组ID", "name": "新增 30 PR"},
      {"batch_id": "round-实际末组ID", "name": "剩余 38 PR"}
    ]
  }]
}
```

这是说明示例，实际 `batch_id` 应从各组 `prepared-round.json` 的 `prepared_id` 读取。登记新轮次时在 `rounds` 中**新增**条目，保留已有成员；不要直接覆盖旧轮次。展示 ID 使用小写字母、数字、点、下划线或短横线。修改 `name` 只影响显示。

一个批次只能属于一个完整轮次。同轮各组的 PR 集合不能重叠；重复将拒绝汇总。**同名 round label 不会自动归组**，不同标签也不会因日期相近自动合并。未准备完整时明确显示缺组和已核对范围。

## 组备注

在轮次概览的“执行组与备注”中点击“编辑备注”→填写多行文本→“保存”；清空保存即删除。每组显示摘要，支持展开全文。备注绑定 `展示轮次 ID / 实际 batch_id`，不会自动继承到下次实验。

备注只写服务器上的 `Log/viewer/notes.json`（由现有 `Log/` 忽略规则排除），刷新、更换浏览器和重启服务后仍在；备份时保留此文件及展示目录。原子替换、服务内写锁和原值检查防止同一服务内的并发覆盖；冲突时页面提示刷新。该服务按现有单实例本地使用方式设计，不提供多实例共享文件的跨进程锁。

GET 页面仍只读。唯一新写接口为 `POST /api/note`；只接受本服务来源的 JSON 和专用请求头，验证轮次及组成员身份，限制正文长度，拒绝符号链接，并将文本转义展示。

## 读取与性能边界

首页核对已有结果索引的 schema、自哈希、source / ledger / seal 文件哈希、冻结目标身份和最新 ledger 事件绑定；不重新跑 prepare 验证链，也不读取 gold。索引已过期时显示未完整核对和原因，不把旧状态冒充当前状态，也不回退到耗时的准备链校验。

首页、轮次详情、PR 详情和比较页统一核对已保存的结果索引及其引用；普通浏览不调用完整的输入准备与基线 AST 校验。点击查看后先显示读取状态，再异步加载内容；评分报告的 schema 校验按报告与 schema 的实际字节缓存，两者任一变化立即重新校验。索引缺失或过期时明确显示不可核对，不自动重建索引或写历史文件。prepare / run / evaluate 的完整校验保持原样。

展示层不生成评分、不启动 Agent / Docker、不修改历史证据。评分表只读宿主机已有数值报告，隐藏 gold 内容不进入新展示模块。

## 验收

根目录一条命令运行离线验收（包含版面、归组、备注、身份、双粒度评分及旧入口回归）：

```bash
python3 sdd-bench/scrapy-sdd/bin/check-testcase
```

HTTP 备注接口另有仅本机回环的测试，无模型或容器：

```bash
PYTHONPATH=sdd-bench/scrapy-sdd python3 -m unittest -q tests.test_sdd_results_layout.HttpLayoutTests
```

当前环境没有浏览器自动化运行时；完成 Python 渲染、HTTP、证据哈希和结构检查，尚未做真实浏览器截图及交互自动化验收。
