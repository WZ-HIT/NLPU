## 这次比较要回答什么

主要问题是：**在相同运行条件下，已有静态事实之外，再提供生成的测试行为说明，能否帮助找回更多需要更新的测试？**

三组都直接从 PR title/body 和任务前 base 定位已有测试，不经过生产代码定位阶段。

| 条件 | A：无 TI | B：仅静态事实 | C：静态事实＋语义意图 |
| --- | --- | --- | --- |
| PR title/body、相同 base 完整源码 | 有 | 有 | 有 |
| 相同测试身份与计分口径 | 有 | 有 | 有 |
| 静态调用、断言、条件、mock、导入、注解、继承等 | 可自行查源码 | 提供已提取事实 | 与 B 完全相同 |
| 静态文件树、来源与关系导航 | 可自行查源码 | 有 | 与 B 完全相同 |
| 模型生成的行为目标、输入、环境与 mock、条件／动作／预期、未知项 | 无 | 无 | 有；缺失继续明确标记 |
| 材料入口说明 | 介绍源码和公共校验器 | 介绍静态读取器 | 介绍相同读取器及可用语义字段 |
| 模型、三种 SDD、通用判断规则、校验器、预算 | 相同 | 相同 | 相同 |

**主比较为 C−B**：估计新增语义材料的实际价值。B−A 是辅助比较，用来观察提供静态材料的价值。C−A 表示整套增强相对直接定位的变化。

新增材料会改变搜索命中、排序、阅读长度和推理过程，这些都属于所测效果。不能将 C−B 宣称为“仅一句摘要的独立效果”。

本版不增加第四组，不单独估计补齐覆盖、判断提示或关系扩展的贡献。如后续需要，必须在新调用之前另发设计修订，明确额外范围。

## 什么保持一致，什么允许不同

三组保持相同任务文本、base、完整测试身份、隐藏标签、三种 SDD 必要流程、模型与配置、运行镜像和工具、公共校验实现及 schema、通用判断规则、草稿与收尾要求、计分代码。

TI-20～22 后续改进的判断规则必须同时进入三组。不能让增强组额外获得更明确的任务定义，又把结果归因于意图表示。正式输出 schema 不变，调查记录不是额外答案来源。

B/C 共享静态字段、权重、匹配算法、排序并列规则、分页规则和源码回查方式。默认 6,000 字节、8 项，上限 12,000 字节、25 项。每组根据实际允许的内容重建检索统计；C 加入语义造成的统计变化属于处理差别，不强行沿用含语义的统计给 B。

本版的文件树与关系均来自静态事实。**不启用由模型生成的文件主题、相同 operation 分组或其他语义关系扩展**，避免在未声明的入口增加第二套增强。完整语义中的 operations 字段仍可按需阅读／搜索。

源码原有注释与 docstring 是公开 base 的一部分，三组均保留。A 组也可以自主理解、搜索源码；无 TI 的含义是没有预先构建的增强材料。

B 的摘要、数据库、上下文、未知项、示例和词频统计都不能残留模型生成内容。尤其不能直接使用已经混合静态与生成未知项的字段。B 的状态表示“仅静态”，不能借用 C 的生成／回退状态透露该测试是否生成成功。仅靠提示 Agent 不读某文件不足以实现隔离。

这些原定构建要求现已通过 TI-24/25 实际材料与小批隔离验收，具体版本见上方修订；不据此声称正式模型实验已经完成。

## 主指标与如何判断结果

**主指标：三个 SDD 的方法级 Macro Recall 等权平均；主差值为 C−B。** 对每个有正例 PR 先算召回，再按 PR 平均，最后对三种 SDD 等权平均。运行失败计零，不能从平均分母中排除。

之所以选召回，是因为当前目标是找回更多需要更新的已有测试。微平均召回会被 PR7808 等大目标集合强烈影响，因此它作为必须报告的辅助指标，不替代主指标。

同时完整报告：

- 每种 SDD 的方法级 Macro／Micro Precision、Recall、F1，TP／FP／FN、预测数与非法身份数。
- 全部 PR 的完成率、直接失败原因、逐 PR 配对差值。
- 至少命中一个、全部召回、预测集合完全正确的任务数。
- 无正例任务的成功正确空输出、成功误报和运行失败，三类分开。
- 有明确标签来源和相同分母的文件级辅助结果；不混用旧轮次不同分母。

预先确定的解释规则：

| 结果 | 允许的结论 |
| --- | --- |
| 主召回差值为正，95% 配对区间下界大于 0，且整体 Macro F1 与完成率没有下降 | 支持语义增强在本开发协议中有收益 |
| 召回上涨，但 F1 或完成率下降 | 存在收益与代价，不能笼统称为改善 |
| 召回差值为正，但区间包含 0 | 观察到上涨，证据不足以认定稳定收益 |
| 主召回没有上涨 | 本协议下未观察到主要收益；保留其他变化供诊断 |

不设“为了过关只选某个 SDD”的规则。逐种 SDD 的结果及误报绝对量必须展示；整体变化不能掩盖单种方法的下降。这些判据是本版事前分析规则，不是用户已批准的最终论文采用标准。

不确定性分析沿用既有方案：以 PR 为单位，对同一 PR 的三组、三种 SDD 和全部重复共同配对重采样，10,000 次，分析种子 20261103，95% 百分位区间。主召回在正例 PR 上重采样，完成率在全部 PR 上分析。不把 90 个 PR×SDD 当成 90 个独立 PR。

只预设一个主比较 C−B；B−A、C−A 和单种 SDD 的区间属于辅助描述，不据此挑选“显著”的赢家。每项只运行一次，因此 PR 重采样不能反映模型重复运行的波动。

## 失败、空输出与标签边界

有正例任务运行失败：P/R/F1 均为 0，TP=0、FP=0、FN=全部目标数，同时单列运行失败。这是执行失败的评分约定，不表示 Agent 正确拒绝了测试。

成功封存空输出：有正例时算漏检；无正例时算成功正确空输出。未成功封存的调查草稿不能补成正式预测。成功但有误报的无正例任务单独统计。

身份解析与非法身份计 FP 的现有规则不变，不在评分前偷偷清理候选。方法内部 API、mock、类型等 AST 内容变化按既有标签协议；只移动、删除、新增、重命名、helper 与纯格式修改继续按原身份和 AST 规则处理。不能为改善指标扩展目标集合。

全部已声明目标终结、预测封存后，才能在宿主机读取新结果对应标签并评分。共同成功子集仅用于辅助诊断，主报告保留全部任务。若决定提前给小批评分并据此调优，须发布新版本，不再将该小批当作原正式比较的无偏部分。
