## 回退究竟由什么造成

| 最终记录的原因 | 版本化测试条目 | 不同输入包 | 能据此确认什么 |
| --- | ---: | ---: | --- |
| 调用前被请求数／费用上限拒绝 | 3,574 | 581 | 这 581 个包没有对应已发送请求账本 |
| 场景证据引用不合法 | 2,216 | 86 | 最终校验未通过，不能作为合法语义发布 |
| provider 输出未完成 | 440 | 14 | 请求发生且有 usage，但没有可发布的完整输出 |
| JSON／记录字段格式错误 | 44 | 3 | 2 包字段错误、1 包 JSON 解析错误 |
| **合计** | **6,274** | **684** | 条目与输入包是不同分母 |

未发现其他未调度且无缓存的输入、网络／HTTP 失败、超大输入、已有请求但缺最终缓存或未分类错误。本结论限于本次实际检查到的材料，不表示恢复器可以省略这些状态。

错误描述只记录“请求数或费用上限”，没有当次拒绝的预算快照，仍分类为“触发上限未明确”。原实现记录与当前实现哈希相符，其默认请求上限为 4,000；账本只有 3,032 条，支持费用／并发预留限制更可能触发的推断。不能由此还原每次拒绝时的瞬时费用，也不能把最终估算费用低于 200 元理解为当时一定能继续发请求。

证据引用错误覆盖全库的 2,216 条，与此前已知目标上 14 条并不矛盾，统计对象不同。当前缓存没有保留逐场景错误位置和完整失败回复；精确到“漏自己的 ID”还是“引用了别人的上下文”的诊断仍属 TI-16，不能仅凭统一错误消息填入细分原因。

范围内 581 包没有请求，2,361 包对应一次请求，335 包对应两次请求。后者包含有限修复，因此请求数不能当作输入包数。跨 base 复用只通过完整包与模型／提示配置相等来连接，不能仅看测试 ID 或方法源码哈希。

另有一个早期探针的成功缓存不属于本次 3,277 个输入包。其账本说明是迁移已有 usage，没有原 request_id；本次保留缺失，用账本文件名标识，单独列出，不虚构一个新请求，也不计入本次覆盖。

全部 3,032 条账本都有完整 input/output usage。按历史代码公式记录的估算费用合计 192.892308 元，包含早期探针；这是历史公式估算，不是 provider 账单，也不是本次新增消费。本次没有缺失 usage，不据此推断历史计价与账单完全一致。

## 缺失集中在哪里

逐 base、逐文件、逐状态及公开源码分层见 [完整审计报告](/data2/wangzuohit/NLPU-experiments/test-intention/ti13-14-20261104-v1/coverage/report.md) 和 [coverage-groups.csv](/data2/wangzuohit/NLPU-experiments/test-intention/ti13-14-20261104-v1/coverage/coverage-groups.csv)。

两处最明显的 base 缺口：

| base | 测试数 | 已生成 | 回退 | 已生成比例 |
| --- | ---: | ---: | ---: | ---: |
| f1694269d8c9437461936ed449e81aa2ccb3b7cb | 2,356 | 1,303 | 1,053 | 55.31% |
| 916039ca4ca79ea4ed38e74d71e25c2584c1925e | 2,460 | 1,422 | 1,038 | 57.80% |

这两个 base 合计 2,091 条回退，约占全库回退的三分之一。它们分别有 1,010 条、964 条上限拒绝记录。全局 88.22% 的生成率不能代表每个 base 都有相近覆盖。

按公开源码特征分层也观察到差异：

| 分层 | 已生成比例 |
| --- | ---: |
| 测试长 1～20 行 | 89.10% |
| 测试长 21～60 行 | 84.64% |
| 测试长 61 行及以上 | 76.91% |
| 存在静态 mock 事实 | 82.69% |
| 不存在静态 mock 事实 | 88.62% |
| 关联上下文 0～4 个 | 93.94% |
| 关联上下文至少 5 个 | 87.49% |

长度、上下文数量等只是公开源码代理特征，不是经验证的任务难度。各分层重叠、同一输入可跨 base 复用，因此不能据此推断“复杂度导致失败”或将条目当独立样本计算显著性。

## 空字段怎样处理

6,274 个回退条目的 summary、operations、inputs、environment_mock、scenarios、uncertainties 均没有生成语义内容，逐条表明确列为缺失。

已生成记录的空数组另记：environment_mock 21,182 条、inputs 487 条、operations 3 条、uncertainties 4,749 条。空数组不等于字段缺失，也不自动等于意图质量错误；是否应该描述某个输入或 mock 要由 TI-19 对照源码审查。不能为了“字段填满”凭空补内容。

## 验收与后续使用

所有条目都有状态和原因，输入包与账本可以单独复算；当前发布内容与来源对齐，完整性检查没有发现差异。另用独立复核入口重算各层计数、缓存键、尝试／provider响应／usage对应，重新核对16,962个输入文件哈希，结果[PASS](/data2/wangzuohit/NLPU-experiments/test-intention/ti13-14-20261104-v1/coverage-verification.json)。6项定向测试通过，覆盖跨base复用、未知消费、旧迁移账本、语义不一致、分组执行清单和禁止网络调用等契约。

标签目标上的旧诊断继续保留在原 host-comparison，本次审计不读取它，也不将其用作补生成优先级。

这份结果支持下一步按公开范围设计恢复：既要处理 581 个调用前拒绝包，也要保留 103 个已经发生调用但未生成成功包的历史记账。恢复逻辑和费用范围尚未实现或授权，本次没有更改失败缓存行为。
