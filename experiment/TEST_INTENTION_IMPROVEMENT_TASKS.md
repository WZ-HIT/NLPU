## 修复之前：诊断与实验设计

### TI-11：逐任务诊断、归因置信程度与影响排序（P0）

**问题依据：**工具错误出现不等于导致运行失败；搜索规划目录可能是必要操作；已有草稿不等于正确、完整或本可成功结束。

- [x] 为原30PR×3种SDD建立90行诊断表，绑定task、method、run、attempt和日志哈希，所有终态均保留。
- [x] 分离直接终止原因、过程障碍、推定根因及证据不足的解释，人工复核关键失败及代表性恢复案例，不只按关键词自动归因。
- [x] 区分首次必要的目录定位、后续重复寻找，以及目录已确认后仍进行的查找。
- [x] 检查工具错误后是否成功替代或恢复，恢复花费多少可观测时间、调用和读取量；低成本恢复不自动升为高优先级。
- [x] 对草稿分别记录结构有效性、源码身份有效性、是否仍有未确认项；已有草稿不自动判为可成功结束。预测正确性仅在宿主机用封存标签事后诊断。
- [x] 按受影响目标数与不同PR数、已知损失、修复成本和归因置信程度提出排序；未知的可节省预算不填零，也不声称已证明反事实收益。

逐任务表至少包含下列字段：

| 记录项 | 具体内容 |
| --- | --- |
| 最终状态与直接终止原因 | Agent结束、封存状态、退出码、错误码；未调用、调用失败、校验失败分别记录 |
| 工具错误及是否恢复 | 错误、替代操作、恢复证据及代价；区分致命与可恢复障碍 |
| 目录定位过程 | 首次定位与重复寻找的事件，是否已知正确路径 |
| 首次草稿、最后校验、结束的时序 | 事件／行号、时间戳及其缺失；包括首次写入、后续修订、最近一次结构／身份校验和终止 |
| 已知预算消耗及缺失情况 | rollout记录、provider usage、时间、调用数、输出字节；注明完整／部分／缺失和测量口径 |
| 根因证据与归因置信程度 | 直接证据、支持与反证、候选解释、置信理由和仍缺的证据 |

置信程度分为“直接证据支持”“存在支持但归因未排他”“证据不足”。直接终止原因明确，也不意味着其之前某个高频操作已被证明是根因。无可靠时间戳时只报告事件顺序，不用行号推算耗时。

**验收：**90项均有诊断行，未知项明确标注；可追溯到原日志及产物，汇总与既有终态和指标一致。先产出诊断表和影响排序，再开始修复。共同成功子集仅作辅助，不取代全体任务主报告。

**涉及位置：**现有`trace-analysis`脚本、封存执行记录和宿主机报告。**依赖：**无需先修改运行器或重新调用模型。

### TI-03：分开结构校验与源码身份校验

**问题依据：**cc-sdd／PR8032草稿根节点为数组，Agent自行校验通过，宿主机发生未捕获异常。该案例直接支持修复格式校验，不代表其他失败都有相同原因。

- [x] **结构层：**检查根节点、`candidates`、`path/symbols/reason`字段、类型、空候选及必要约束；先检查根节点类型。
- [x] **身份层：**检查路径是否位于允许base、符号是否存在且为测试、限定名是否明确；报告符号歧义和不允许的路径。
- [x] Agent与宿主机共享实际校验实现、schema和版本；记录实现／schema哈希，避免两套逻辑各自认为通过。
- [x] Agent校验器只读取公开base和公开契约，从公开源码构建必要身份信息；不挂载宿主机标签或宿主机评价索引，不导入标签构建模块。
- [x] 返回稳定错误码、层级和字段位置，例如根节点类型、`candidates[0].symbols[1]`；相同输入在两端得到相同诊断。
- [x] 身份错误不自动修正、丢弃或依据gold过滤。现有无效预测计FP与整次失败计零的差别需保留；若引入严格拒绝改变终态，先在TI-12a明确协议，不静默改变评分。

**验收：**结构例子覆盖合法空／非空、根数组、缺失字段、错误类型；身份例子覆盖越界路径、非测试符号、缺失与歧义限定名。两层结果可独立检查，同版本两端一致；根数组不触发未捕获异常。

**涉及位置：**`batch/stages.py`、公开校验模块、schema及回归检查。**依赖：**TI-11、TI-12a、TI-02。

### TI-04：保存可修订草稿并验证收尾路径

**待核实信号：**12项预算失败前出现草稿；这不证明它们正确、完整或本可顺利结束，先依据TI-11逐项检查时序。

- [x] 调查草稿允许不完整且持续修订，不提前锁死候选；待确认项存放在独立进度文件，正式输出仍只有规定的`candidates`结构。
- [x] 使用同目录临时文件与原子替换保存完整JSON，中断后保留最近一次完整版本，区分过程草稿与正式输出。
- [x] 根据可靠的预算余量和剩余时间安排收尾，同时预留必要产物、一次最小校验及结束开销；无可靠余量时记录近似依据和限制。
- [x] 限制重复校验及“校验—扩写—再校验”的循环；同一草稿未变时避免重复检查，失败后的修正次数设明确上限并在设计中固定。
- [x] 模拟预算耗尽、时间到限、工具错误、校验失败和中途退出，核查草稿完整性、错误状态和正式封存边界。

**验收：**离线故障检查证明最近完整草稿可辨识、未完成草稿不被误封存，结束路径可达；真实收益须同时看完成率与最终召回，不能仅以预算失败减少判定有效。沿用已定预算，不补算历史失败草稿。

**涉及位置：**Detect说明、草稿写入与校验工具、运行器预算／时间提示。**依赖：**TI-01～03及TI-11时序诊断。

### TI-05：区分修改类型、身份计分与更新必要性

**身份与计分规则：**已有方法内部的引用替换，不因行为不变而自动排除。**预测依据规则：**选择该方法必须有任务要求与当前源码的对应证据，不能因它含导入、mock、注解等字段就认定需要改，也不能推测未来补丁必然采用某种写法。

- [x] 把上述两条规则分别写入说明，区分“属于可计分的修改类型”与“此任务有依据要求修改该方法”。
- [x] 明确共享helper足以完成改动时，不把所有使用它的测试方法自动选中；对不确定必要性保存理由。
- [x] 将下列已核查口径写入公开协议说明，保持标签不变，不用提示扩张目标；若希望改变目标，另列协议版本讨论。
- [x] 提供独立构造的成对示例；真实PR的gold与最终patch只用于宿主机诊断，不进入Agent示例或意图。

2026-11-03核查现有代码得到的规则：

| 情形 | 当前标签处理 |
| --- | --- |
| 在base有明确身份，记录为modified，原源码对齐且函数AST变化 | 计入；包括函数签名、注解、装饰器及方法体的AST变化 |
| 纯格式／注释／位置变化，函数AST不变 | 以`mechanical_ast_equal`排除；不将字符串内部内容变化简单视为格式变化 |
| 行为等价但AST不同的改写 | 当前不做语义等价证明；满足其余条件时仍计入 |
| 原记录为新增、删除、改名，或检测到方法自身改名 | 排除；helper／fixture不作为测试方法目标 |

实现依据为[身份与AST比较](../sdd-bench/scrapy-sdd/batch/testcase_identity.py)、[标签构建](../sdd-bench/scrapy-sdd/batch/testcase_labels.py)。它反映可观察源码修改标签，不证明所有标签都是行为上不可避免的改动。

成对示例至少覆盖：

| 任务与base证据 | 应作出的判断 |
| --- | --- |
| 任务明确要求迁移API，已有方法直接依赖必须替换的旧API | 有更新候选依据；仍检查旧接口是否继续兼容及方法本身是否需改 |
| 仅生产内部重构，测试接口和断言仍有效 | 不能仅凭相关性选中 |
| 修改共享helper即可满足任务，测试方法内容无需改 | 与方法级目标区分，不批量扩展到使用者 |

**PR8002诊断结论：**按当前协议，32个迁移方法被记录为32删除＋32新增而排除；将这些旧身份报为更新目标属于过度扩张，不是正确的批量召回。3个保留身份并修改内容的方法才是本轮目标。Spec Kit为0TP／32FP，另外两种方法为3TP／32FP。若研究希望把移动／迁移也纳入目标，那是任务定义与标签边界的另一个问题，不改本轮结论。

**验收：**公开说明明确AST与语义等价的区别，成对示例同时约束漏选与过选；预测必须引用任务与base依据。原标签、候选schema和历史评分不变。

**涉及位置：**Detect提示、程序协议说明；标签代码仅供核对。**依赖：**TI-11、TI-12a；与运行修复分包验证。

## P1：先字段契约，再展示与排序
