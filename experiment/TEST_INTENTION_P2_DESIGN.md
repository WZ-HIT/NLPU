# P2：新增事实与关系的检查方案

2026-11-03，v1。继续使用30个开发PR、22个base，保持P1公开查询、测试身份、字段权重和排序公式。开发标签此前已用于诊断，本阶段不是盲测。不运行模型、不读取68个独立测试PR的标签。

## 先检查什么

P1中PR7968的公开任务是类型更新，PR7808的公开任务涉及工厂构造。P1已保存直接调用和表达式，但没有独立保存类型注解、完整类继承来源及相关初始化／helper内部的调用事实。本阶段检查这些缺口，不预设它们解释了全部漏检。

TI-09限定新增五类事实：

| 字段 | 原源码中取什么 | 如何限制误解 |
| --- | --- | --- |
| annotations | 参数、返回值、局部变量的类型注解 | 字符串注解不执行，不宣称是运行时类型 |
| inheritance | 测试所属类及能静态找到的祖先类的base表达式 | 记录来源链；多候选、外部基类和循环保留未知，不模拟完整MRO |
| context_calls | 已有证据明确关联的初始化、fixture或直接helper定义中的调用 | 不扩展新的任意生产候选；每测试最多4个定义，每定义最多16次调用，省略量单列；关联不证明执行 |
| imports | 上述作用域实际引用到的导入别名及完整导入名 | 保留条件、局部遮蔽和多绑定的疑点；不把整个文件所有导入复制给每个测试 |
| guards | 定义外层及所用导入所在分支的条件表达式 | 区别已有方法内部conditions；不推断条件真假 |

资源生命周期等其他方向留为缺口。新事实只从锁定的纯base读取AST，提取过程不导入或执行项目。每项绑定源码路径、字符位置、文件SHA与原文；解析后的导入名和候选目标明确标为派生信息。原证据数据库、语义、场景和未知项保持字节不变，新证据另存并去重。

默认search仍给短结果；新增字段权重固定为1，不按PR或标签设专用加分。match可回查事实原文及来源；maintenance按需展开。原P1包不修改。

## TI-10启动条件

先用固定P1首屏前4个完整结果作为种子，审查已有关系：fixture／初始化定义与共享调用依赖分别统计，连接的测试数限制在2～12。区分“未进入匹配集合”与“只未进入首屏”。使用宿主机开发标签只做事后诊断，不据此选运行时种子。

初始审查结果：明确静态上下文没有到达遗漏正例；弱共享调用在PR8022到达了一个首屏遗漏正例，但该正例本已在直接匹配集合。此结果不支持默认增强neighbors。待TI-09完成后，再用新增继承事实检查一次。若仍没有经源码复核的匹配集合外到达案例，TI-10交付审查及暂缓决定，不强行开发关系排序。

## 预先固定的离线比较

每查询6,000 UTF-8输出字节、最多25个单元；查询直接复制P1封存文件，不另行选词。比较：

- P：冻结P1 R，已有字段与字段BM25。
- N：已有字段加五类新事实，字段BM25；新增字段权重1。
- A：仅新增annotations，其他条件同N。
- C：新增inheritance/context_calls/imports/guards，其他条件同N。

不同字段组独立计算词频统计，避免用未启用字段的文档频率污染消融。固定第一条结果的按需回查成本，不通过gold挑一个更便宜的例子。先封存全部排名和真实页面，再运行宿主机评价。报告全部30PR、29个正例PR／361个目标、空目标任务、宏／微候选召回、首个命中位置、集合覆盖、字节和逐PR变化，保留下降。

按公开文本提前分组：type／typing／annotation／check_untyped_defs属于类型任务；build_from_crawler／class／classes属于构造或类结构任务；其他PR仍纳入主报告。分组只用于解释，不用于运行时路由或权重。

若TI-10通过启动条件，实现前另记扩展预算和比较组；不得把额外调用视作与单页等成本。离线收益不等于SDD最终召回或provider token节省。
