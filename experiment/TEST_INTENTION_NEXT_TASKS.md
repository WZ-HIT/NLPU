# 测试意图后续任务清单：补齐覆盖、改进更新判断、验证实际收益

版本：v11，2026-11-11。状态：TI-13～28在用户修订的B/C范围内完成；180项全部终结，159项成功封存、21项预算失败，独立计数与配对检查PASS。实际费用和部分usage未知，均明确披露。详见[最终报告](TEST_INTENTION_STAGE_C_RESULTS.md)。

本清单承接用户选定的三项方向：先修复生成覆盖，再建立任务与源码敏感点的对应，最后通过匹配环境比较确定收益。它延续原[TI-01～TI-12清单](TEST_INTENTION_IMPROVEMENT_TASKS.md)，使用TI-13～TI-28编号，保留原任务的完成记录。实验设计在修改之前固定，实际模型比较放在离线验收之后。

v1只交付任务规划；v2根据用户要求完成[TI-13全库审计](TEST_INTENTION_TI13_COVERAGE_RESULTS.md)和[TI-14比较设计](TEST_INTENTION_TI14_COMPARISON_DESIGN.md)。生成意图与SDD定位是两类不同的模型调用；下面分别列出运行条件与预算准备任务，不把这份清单当作新增调用授权。已有实验和缓存保持可复核，原始历史基线不重跑。

## 已核实的问题与本次边界

| 已知事实 | 对任务安排的影响 |
| --- | --- |
| 原30PR有361个方法级目标条目，其中165个有语义意图、196个仅静态回退 | 检查实际语义覆盖，不能只统计测试ID是否齐全 |
| 196个回退目标中182个对应请求数／费用上限，14个对应证据引用校验失败 | 分别处理预算调度与生成校验；条目数不等于请求数 |
| PR7808有175个目标，其中172个没有语义意图 | 用于宿主机诊断，但不能只按这些已知目标补生成 |
| 生成器命中既有缓存时，失败缓存也会直接返回 | 单纯重跑旧命令不能补齐，需先设计恢复行为 |
| PR8002、8040出现已读到目标后仍排除；PR8017出现大范围批量误报 | 同时处理过严排除与过宽选择，不能只增加候选数量 |
| 现有比较同时改变运行环境、提示、检索和表示 | 旧结果继续作为历史参照，新匹配组负责区分贡献 |

“全库”在本阶段指原30PR涉及的22个公开base及其53,249条版本化测试记录；每个base构建一次，由三种SDD共享。不是只处理361个标签目标，也不是重新扩展到其余68PR涉及的base。其他仓库后续沿用同一流程，不能直接当作本阶段已覆盖。

输入继续为PR title/body和任务前base，输出仍定位到已有测试函数／方法，属于方案一。生成意图只使用base源码，不接收PR标签、未来实现、最终测试补丁或方案二的生产代码候选。文件树与关系用于导航，不限制全部测试的可搜索范围。
