执行根目录中的 `config.toml` 明确开启 rollout budget，`limit_tokens = 100000`。此前设计记录中“未发现独立累计预算”的说法核查不完整，现予补正；历史每次运行实际读取的配置字节仍不能独立证明完全相同。该预算的内部计算不能直接等同于 provider 的累计 input/output token。

两组都成功且有正例的相同任务，仅作次级观察：OpenSpec 10 项的 macro recall 为 81.0% → 81.8%；Spec Kit 5 项为 80.0% → 80.0%；cc-sdd 4 项为 100.0% → 75.0%。这些样本较少，不能替代完整任务结果。

结论：这版增强在当前运行条件下没有提高整体定位指标。后续需要先分析材料读取量与预算耗尽的关系；现有证据不能把全部降幅归因于表示内容。未自动扩大实验或重跑失败请求。

## token 消耗的阶段说明

表示预生成发生在 Detect 之前：静态解析 → 独立 DeepSeek 生成 → 发布并冻结到新仓库 → SDD Detect 阅读 → 宿主机评价。预生成使用自己的请求／费用边界，不扣减 Detect 的 rollout 额度。每项 PR × SDD 的 Detect 是一个新 Agent 进程，预算为 100,000 token；10,000 是剩余预算提醒阈值之一，不是总上限。

Detect 会为读取已有表示、原源码、工具输出及后续推理和规划消耗预算。生成的文件放在磁盘上不会自动消耗这项预算，读入定位上下文后才会影响消耗。

日志复核覆盖全部 90 项：90 项均执行过涉及 `test-intentions` 的读取命令。失败组平均有约 464,025 个字符的工具输出，其中涉及表示的命令平均输出约 276,424 字符；成功组相应为约 263,892 和 114,746 字符。这些是命令日志输出字符量，不等同于实际计入上下文的 token，且混合查询命令也可能包含源码输出。

例如 PR 7511 的 cc-sdd 定位中，一条命令同时打印 manifest 与 relations 的前 50,000 字符，输出约 100,105 字符；PR 7702 的 cc-sdd 定位中，一次针对表示记录的宽泛全文搜索产生约 274,736 字符输出。当前 JSON 还同时保存摘要、原测试源码、静态事实及展开上下文，宽泛读取容易带入大量重复信息。

因此，已确认的直接终止原因是预算耗尽，日志也证实了较大的材料读取量；额外表示具体贡献了多少 token 以及是否是唯一原因，尚不能从这些字符统计精确归因。后续应先把面向定位的简短索引／行为描述和按需查证的详细证据组织好，并控制每次读取规模，再判断表示收益。没有修改预算或启动新实验。
