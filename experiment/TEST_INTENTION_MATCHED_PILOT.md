## 三组实际提供什么

| 输入 | A：无 TI | B：仅静态事实 | C：静态＋语义 |
| --- | --- | --- | --- |
| 原 title/body、相同公开 base | 有 | 有 | 有 |
| TI 文件包 | 不挂载 | 静态包 | 增强包 |
| 测试身份、静态事实、上下文和关系 | 自行查源码 | 提供已保存事实 | 与 B 相同 |
| 生成摘要、输入、mock、场景与模型未知项 | 无 | 无 | 保留已验收语义 |
| 检索统计 | 无预建 TI 索引 | 只从本组静态内容重算 | 从本组静态与语义重算 |
| 判断、记录、最终输出与评分规则 | 三组相同 | 三组相同 | 三组相同 |

正式材料位于 [materials](/data2/wangzuohit/NLPU-experiments/test-intention/stage-c-20261109-v1/materials)。B、C 各有 22 个 base、53,249 条测试；C 保留 53,145 条语义和 104 条回退，不宣称全量语义正确。

B 从新数据库创建，避免“删除字段后旧语义仍留在 SQLite 空闲页”。同时重建卡片、逐文件摘要、完整检索字段、向量、词频及长度统计。所有测试统一显示 `STATIC_ONLY`，不泄露哪些测试生成成功。未知项来自原始静态记录，不从混合了模型描述的列表中猜测扣除。

C 的每个测试、语义与已验收阶段 B 输入逐项核对。B/C 使用相同读取代码、静态事实、维护事实、源码身份和静态关系；不加入语义文件主题或额外关系扩展。原源码注释与 docstring 在所有组保留。

## TI-25 怎样验证运行环境

三个比较组分别准备独立的轮次、测试工作区、规划目录、日志、封存目录和账本。全部 27 项必须准备完成，才能派发第一个正式 Agent。各组任务文本、base、测试身份和初始化 SDD 文件需要一致，材料入口差异单列。

容器检查使用实际镜像、UID/GID `1007:1007`、只读源码和材料、指定可写规划目录及相同 bubblewrap 策略。检查阶段关闭网络、不挂模型凭据，运行工具版本、公开校验器、草稿收尾及读取器。两种小批 base × 三种 SDD × 三组，共 18 种环境组合；全部 27 个准备工作区另检查实际输入清单。

失败路径包括：错误根节点、非法或有歧义的测试身份、未完成草稿、写入中断、缺失准备或预算边界、工具／Agent 失败、额度拒绝、已开始但进程中断、重复启动，以及未全部终结就尝试评分。相关自动检查共 69 项通过；27 个工作区已全部准备，18 个实际容器组合全部 PASS，22 个实际镜像身份已核对。结果见 [offline-acceptance.json](/data2/wangzuohit/NLPU-experiments/test-intention/stage-c-20261109-v1/offline-acceptance.json)。冻结清单也包含准备后实际使用的 Compose、proxy、初始化及任务文件；不锁定运行时需要写入的规划与输出文件。

宿主机准备步骤保留原有隐藏材料隔离审计；其结果不提供给模型，不用于挑选候选。正式预测和排名全部终结后，才调用宿主评分器解释新模型结果。

## TI-26 固定范围与执行方式

三条 PR × 三种 SDD × 三组 × 一次正式尝试，共 **27 项**。沿用 `deepseek-flash/high`，每项 100,000 rollout、2,700 秒，上限合计 2,700,000 rollout；这不是 provider token 总数，也不是人民币费用。

按原冻结清单保留每个 PR×SDD 内的 A/B/C 顺序，最多三个 SDD 队列并发。A/B/C 的同一 PR×SDD 使用相同固定网络子网与 Compose 标识，因此该组合中的三组串行；不同组合允许重叠。实际开始／结束时刻写入账本。这个调度细节在任何新模型调用前公开，不把清单上的全局编号冒充实际严格开始顺序。

每项目标在调用前持久写入开始记录，只能正式启动一次。失败不重试；进程中断留下 `DETECT_RUNNING` 时，续接会先停下核查，不能当作没发出请求。额度／凭据拒绝后停止新派发，保留在途结果，未开始项记为明确阻塞。模型凭据不写入记录，不执行充值。

执行已作为独立后台进程启动，日志为 [workflow.log](/data2/wangzuohit/NLPU-experiments/test-intention/stage-c-20261109-v1/workflow.log)。全部 27 项终结后自动进入宿主评价。运行前的零调用离线报告保持原样；旧状态及文档保存于 `before-ti26-start-20261110/`，实时状态由 `pilot-ledger.sqlite3` 和控制器 `status` 提供。
